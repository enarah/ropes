# Slice 4 dependency security review

Review date: 2026-11-16. Baseline: `be8e7ea79a615e88349da78f1fd230fd3f071623`. No dependency versions or lockfile entries were changed. `npm audit`, `npm audit --omit=dev`, `npm explain` and source inspection were used; no exploit was attempted and no deployed host was inspected.

## Counts and reproducible evidence

The original install reported **23 packages: 12 moderate, 10 high, 1 critical**. A fresh audit against the unchanged lockfile reports **22 packages: 11 moderate, 10 high, 1 critical**, representing 36 unique advisory IDs. npm counts affected packages, including parents affected through a dependency; these are not 22 independent exploitable bugs. There is no archived original advisory JSON identifying the former 23rd package, so its identity/removal cannot responsibly be inferred from the count alone. The current complete inventory is in [the audit snapshot](evidence/spot-dependency-audit-2026-11-16.json), including lockfile SHA-256, installed versions/paths, advisory URLs, affected ranges and npm's proposed fixes. Registry advisory metadata can change independently of this repository.

`--omit=dev` reports **8 packages: 1 moderate, 6 high, 1 critical**. This is installation classification, not proof of execution. In particular Prisma CLI is a development dependency also retained as an optional peer of `@prisma/client`; npm classifies it and its tooling subtree as production-present. The existing sandbox Dockerfile runs unrestricted `npm ci` and copies the complete tree, so development dependencies are also physically present in that image. This review does not assert the contents of a running deployment.

## Critical/runtime priorities

`next@16.3.4` is the critical package entry and aggregates 11 advisories, including three RCE advisories. The actual SPOT CLI imports Prisma's generated client/PostgreSQL adapter, dotenv, saxes and its own tracking modules; it does not start Next.js, use sharp or import the Prisma maintenance CLI. No audited vulnerable operation was identified on that command's import/call path. This is source-based reachability analysis, not a guarantee about every transitive dependency or future code change.

## Recommendation

The requested audit investigation is complete, not remediation. No `npm audit fix`, installation refresh or dependency upgrade was run. Prioritise a separate security change for Next/sharp, then coordinated Prisma/toolchain updates; re-audit and repeat validation after each. Server Actions DoS is a concrete matching runtime concern and conditional critical paths remain in the installed runtime packages. This work is suitable for merge **review** of the isolated SPOT slice, subject to reviewer acceptance of the existing dependency risk; it is not a clean security bill or approval for live-network deployment.
